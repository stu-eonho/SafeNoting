# 11. 수위 예측 모델 설계

> 작성 2026-08-16 · 표준 Transformer를 그대로 가져다 쓰지 않고,
> **이 문제의 물리 구조에 맞춰 개조**하기 위한 설계 문서.

---

## 1. 이 문제는 일반 시계열 예측과 무엇이 다른가

설계를 정하기 전에, 우리 문제의 성질부터 못박는다. 여기서 구조가 결정된다.

| 특성 | 일반 벤치마크(ETTh, Weather 등) | **우리 문제** |
|---|---|---|
| 예측 대상 | 전 구간 평균 성능 | **급상승 구간만 중요** |
| 오차의 비용 | 대칭 | **과소예측 = 사망, 과대예측 = 헛걸음** |
| 변수 간 관계 | 불명확 | **상류→하류 전파, 시차까지 측정됨** |
| 정상성 | 대체로 정상 | **강한 비정상** (평수 1.5m ↔ 홍수 10m) |
| 사건 빈도 | — | **극단 사건이 희소** |

이 다섯 가지가 각각 설계 결정 하나씩으로 이어진다.

---

## 2. 표준 Transformer를 그대로 쓰면 실패하는 이유

### 2.1 DLinear 문제

*"Are Transformers Effective for Time Series Forecasting?"* (Zeng et al., AAAI 2023)에서
**단순 선형 모델 DLinear가 Informer·Autoformer·FEDformer를 모두 이겼다.**

이유는 단순하다. 시계열 예측 성능의 대부분은 **추세(trend)를 그대로 이어 그리는 것**에서 나오고,
그건 선형 사상으로 충분하다. Transformer는 그 위에 얹을 게 별로 없는데,
파라미터만 많아서 과적합한다.

> **따라서 "Transformer를 쓴다"는 결정 자체가 정당화를 요구한다.**
> 우리 설계는 이 정당화를 **구조 안에 내장**한다 (→ §3).

### 2.2 손실 함수 문제

MSE로 학습하면 모델은 **표본이 압도적으로 많은 평수위(1.5m)에 최적화**된다.
20년 중 경보수위(8.0m)를 넘는 시간은 극히 일부다.
이대로 두면 "항상 1.5m라고 답하는 모델"이 MSE 기준으로 훌륭한 모델이 된다.

### 2.3 정상성 문제

수위는 비정상 시계열이다. 학습 구간의 분포와 검증 구간의 분포가 다르다.
정규화 없이 넣으면 극단값에서 외삽(extrapolation)이 무너진다.

## 3. 제안 구조 — Linear를 "출력 헤드"가 아니라 "병렬 경로"로

### 3.1 핵심 아이디어

Linear를 Transformer **뒤에** 붙이는 게 아니라, **옆에** 나란히 둔다.

```
                    ┌─────────────────────────────────┐
   입력 시계열 ──────┤                                 │
   (48h × 변수)     │  [경로 A] 선형 — 추세 담당        │──┐
                    │   시계열 분해 → Linear           │  │
                    │   (DLinear 구조)                 │  │
                    └─────────────────────────────────┘  │
                                                          │  α (학습 가능한 게이트)
                    ┌─────────────────────────────────┐  │
                    │  [경로 B] Transformer — 잔차 담당 │──┤
                    │   변수 토큰화 → Self-Attention   │  │
                    │   × 2~3층 → Linear 헤드          │  │
                    └─────────────────────────────────┘  │
                                                          ▼
                                          출력 = A + α · B
```

**왜 이렇게 하는가:**

1. **성능 하한이 보장된다.** Transformer가 학습에 실패해도 α→0이 되면서 최소한 DLinear 성능은 나온다.
2. **Transformer가 필요한지를 구조가 스스로 답한다.** 학습 후 **α 값과 경로 B의 기여도를 측정**하면 된다.
   α가 0에 수렴하면 → *"이 문제에 Transformer는 불필요하다"* 가 실험 결과로 증명된다.
   이건 LightGBM 폐기와 같은 방식의, 데이터로 뒷받침된 결론이다.
3. **역할 분리가 물리적으로도 자연스럽다.** 추세(물이 차오르는 기본 흐름)는 선형이고,
   비선형 잔차(제방 월류, 배수 한계, 지류 합류)를 Transformer가 맡는다.

> 초기 아이디어였던 "후반에 linear를 단다"는 경로 B 끝의 **출력 헤드**로 들어간다.
> 여기에 더해 **경로 A 자체를 linear로 병렬 배치**하자는 것이 이 설계의 요지다.

### 3.2 경로 B를 어떤 Transformer로 할 것인가

| 후보 | 토큰 단위 | 우리 문제 적합성 |
|---|---|---|
| PatchTST | 시간 패치 (변수 독립) | **변수 간 관계를 못 본다** — 상류 정보가 핵심인 우리 문제와 상충 |
| Informer / Autoformer | 시간 스텝 | △ 긴 시퀀스용. 우리는 48h면 충분해 이점이 없다 |
| **iTransformer** | **변수 (inverted)** | **변수 간 attention** — 상류→하류 관계를 직접 학습 |

**채택: iTransformer 계열 (변수를 토큰으로).**

우리 문제에서 가장 중요한 신호는 "3시간 전 환희교 수위"다.
즉 **변수 간 상호작용이 본질**이므로, 변수를 토큰으로 놓고 attention을 거는 구조가 맞다.
attention 맵이 곧 "어느 상류 관측소가 예측에 기여했는가"가 되어 **해석도 가능**하다.

## 4. 물리 지식을 구조에 주입한다

우리는 이미 **시차 상관으로 상류 관계를 측정**해뒀다. 이걸 모델이 처음부터 다시 배우게 할 이유가 없다.

| 관측소 | 선행시간 | 상관 |
|---|---:|---:|
| 팔결교 3011635 | **-2h** | 0.991 |
| 환희교 3011660 | **-3h** | 0.974 |
| 흥덕교 3011645 | -4h | 0.940 |
| 성산2교 3011653 | -4h | 0.928 |
| 향정동 3011663 | -6h | 0.844 |
| ~~미호교 3011685~~ | **+1h** | **영구 제외 (미래정보 누수)** |

**적용 방법 — 시차 정렬(lag alignment):**

상류 변수를 입력에 넣을 때 **측정된 lag만큼 미리 시프트**한다.
모델이 attention으로 "3시간 전 값이 중요하다"를 발견할 필요가 없어지고,
그 표현력을 비선형 잔차 학습에 쓸 수 있다.

```python
# 물리적으로 확인된 전파 시간을 그대로 반영
LAG = {"3011635": 2, "3011660": 3, "3011645": 4, "3011653": 4, "3011663": 6}
# x_upstream[t] ← wl_상류[t - LAG]
```

이건 **inductive bias 주입**이며, 표본이 적은 극단 구간에서 특히 효과가 크다.

## 5. 손실 함수 — 재난 예측은 대칭이 아니다

### 5.1 비대칭 손실

> **과소예측(실제보다 낮게 예측)은 사람이 죽는다. 과대예측은 헛걸음이다.**
> 두 오차의 비용이 같을 수 없다.

```python
def asymmetric_weighted_loss(pred, true, cur):
    err = pred - true
    under = (err < 0)                      # 과소예측
    w_dir = torch.where(under, UNDER_W, 1.0)      # 과소예측 가중 (예: 3.0)

    # 고수위 구간 가중 — 평수위 표본에 묻히지 않게
    w_lvl = 1.0 + LEVEL_W * torch.clamp(true - ALMWL, min=0)

    # 급상승 구간 가중 — 우리가 진짜 맞혀야 하는 구간
    w_rise = 1.0 + RISE_W * torch.clamp(true - cur, min=0)

    return ((err ** 2) * w_dir * w_lvl * w_rise).mean()
```

### 5.2 분위수 출력 (선택)

단일 값 대신 **여러 분위수를 동시 출력**하면 "최악의 경우" 안내가 가능해진다.

```
출력: q10, q50, q90
안내: "3시간 뒤 예상 9.2m (최악 10.4m) — 위험수위 초과 가능"
```

재난 안내에서는 q90(보수적 추정)을 판정에 쓰는 게 옳다.

## 6. 정규화 — 비정상성 대응

**RevIN (Reversible Instance Normalization)** 을 입출력에 건다.
입력 창(window)마다 평균·분산을 제거하고, 출력에서 되돌린다.

추가로 **delta 예측**을 병행한다. 절대 수위가 아니라 **현재 대비 변화량**을 예측하고,
마지막에 현재 수위를 더한다.

```
모델 출력 = Δ(t+h)
최종 예측 = 현재 수위 + Δ(t+h)
```

이 둘을 같이 쓰면 학습 구간에 없던 극단 수위에서도 외삽이 안정된다.

## 7. 입출력 명세

```
입력  lookback = 48시간
  ├ 타겟 수위             (1)
  ├ 상류 수위 5개 (lag 정렬) (5)
  ├ 상류 변화량 5개         (5)
  ├ 강수: 1/3/6/12/24h 누적  (5)
  ├ 미래 강수 예보 (운영시)   (3)   ← 단기예보 POP/PCP
  └ 시간 인코딩 (월, 시각)   (4)
                        총 23개 변수

출력  multi-horizon 동시 예측
  h = 1, 2, 3, 6 시간 후의 Δ수위   (× 분위수 3)
```

**multi-horizon으로 하는 이유**: 대피 판단에는 한 시점이 아니라 **시간 곡선**이 필요하다.
"3시간 뒤 위험수위 도달" 같은 안내를 하려면 곡선 전체가 있어야 한다.

## 9. 검증 계획 — 단계적으로, 각 단계에서 폐기 가능

각 단계는 **이전 단계를 유의하게 이겨야만** 다음으로 넘어간다.

| 단계 | 모델 | 통과 조건 | 실측 |
|---|---|---|---|
| 0 | Persistence | (기준선) | 급상승 0.752 |
| 1 | 선형회귀 (수위 lag) | 0을 이긴다 | 0.542 (+27.9%) |
| 2 | 선형 + 강수 | 1을 이긴다 | **0.443 (+41.1%)** |
| 2b | + 상류 관측소 | 2를 이긴다 | 수집 중 |
| 3 | **DLinear (경로 A 단독)** | 2b를 이긴다 | - |
| 4 | **경로 A + B (제안 구조)** | **3을 급상승 구간에서 이긴다** | - |
| 5 | 물리 lag 정렬 추가 | 4를 이긴다 | - |
| 6 | 비대칭 손실 적용 | 과소예측률이 유의하게 감소 | - |

### 9.1 확정된 베이스라인 (2026-08-16 실측)

```
데이터  : 미호강교 189,300건 (2005~2026, 22년) · 센서오류 15건 제외
분할    : 학습 ~2019 (131,211건) / 검증 2020~2026 (58,059건)
검증표본: 홍수기 25건 · 급상승(3h +0.3m↑) 655건

                     전체     홍수기    급상승   과소예측률
① Persistence       0.098    1.010    0.752     100.0%
② 선형(수위 lag)     0.069    0.624    0.542      94.2%
③ 선형(+강수)        0.060    0.560    0.443      86.7%
④ 선형(변화량 예측)   0.060    0.560    0.443      86.6%
```

> **Transformer가 넘어야 할 선: 급상승 RMSE 0.443 m, 과소예측률 86.6%**

**주의**: ③의 개선은 전부 **강수** 덕분이다. 상류 관측소 CSV가 수집 중이라 실제로는
입력에 들어가지 않았다(파일 부재 시 현재 수위로 대체됨). 상류 반영 후 2b로 갱신한다.

### 9.2 이 측정에서 얻은 교훈 — 평가 구간 분리는 유지하되, 이유가 바뀌었다

1년치(2023년)로 예비 측정했을 때는 **전체 RMSE와 급상승 RMSE의 순위가 정반대**로 나왔다.
그러나 22년치에서는 **세 구간 모두 순위가 같다**. 1년치 결과는 학습(1~9월)과 검증(10~12월)의
계절이 달라서 생긴 왜곡이었고, 데이터가 늘자 사라졌다.

그럼에도 구간 분리는 계속 필요하다. 이유가 "순위가 뒤집혀서"가 아니라 **"오차 크기가 7배 다르기"** 때문이다.

```
전체 RMSE   0.060 m   → "6cm 오차, 훌륭한 모델"
급상승 RMSE 0.443 m   → 정작 맞혀야 하는 구간에서는 44cm 틀린다
```

전체 지표만 보고하면 모델의 실제 성능을 7배 과대평가하게 된다.

### 9.3 데이터 정제 — 실측에서 발견한 센서 오류

22년치를 받고 나서야 드러난 문제다.

```
2023-05-16  1.51m → 11.27m (1시간) → 10시간 유지 → 1.15m 복귀
            당일 청주 강수량 0.0mm
```

처음에는 **강수 대조**(급상승 + 강수 없음 → 오류)를 규칙으로 삼았으나,
진짜 홍수인 2020-08-03(직전24h 11mm)과 2006-07-28(32.5mm)까지 오탐했다.
청주 ASOS 한 지점으로 진천·음성·청주에 걸친 미호천 유역 전체를 대표할 수 없기 때문이다.

대신 22년 전체의 **1시간 변화율**을 조사하자 뚜렷한 경계가 있었다:

| | 1시간 최대 상승 |
|---|---:|
| 센서 오류 (2023-05-16) | **+9.75 m/h** |
| 진짜 홍수 최대 (22년 전체) | +1.71 m/h |
| 2017 중부호우 | +1.59 m/h |
| 오송 참사 | +0.70 m/h |

**이 하천에서 1시간에 2m 이상 오르는 일은 물리적으로 발생하지 않는다.**
이를 주 규칙으로 삼아 재탐지한 결과 **2023-05-16 한 구간(15시간, 전체의 0.008%)만** 걸렸고,
진짜 홍수는 모두 보존됐다. (이 v1 규칙의 결함과 v2 재설계는 §9.6 참조 → `scripts/clean_waterlevel2.py`)

**4단계에서 못 이기면 Transformer를 버리고 3단계 모델로 간다.**
그 경우 결과물은 *"이 문제에서 Transformer는 불필요함을 실험으로 확인했다"* 가 되며,
α 게이트 값이 그 근거가 된다.

```
전국 59개 관측소 홍수기(6~9월, 2005~2026) 수집 → 47개 사용
train 33개 관측소  666,057표본  급상승 17,303   ← 단일 관측소 때는 1,150개였다
val    7개 관측소   88,606표본  급상승  6,370
test   7개 관측소   86,335표본  급상승  1,613
```

**관측소 단위 분할**이므로 test는 학습이 한 번도 보지 못한 하천이다.
val로만 모델을 고르고 test는 최종 1회만 평가했다 (이전의 데이터 누수 결함 해소).

### 동일 조건 비교 — Transformer 채택

```
TEST = 처음 보는 관측소 7곳 · 상류정보 없음 · 급상승 1,613건

모델                    전체 RMSE   급상승 RMSE   과소예측률
① Persistence            0.0156      0.0947      100.0%
② 선형회귀(Ridge)         0.0124      0.0678       92.3%
③ Transformer(A+αB)      0.0380      0.0567       44.9%
                                     ↑ ②대비 -16.4%   ↑ -47.4%p
```

미터 환산(test 평균 경보수위 9.41m): 급상승 **0.638m → 0.534m**

> **§9 단계 4 통과.** 급상승 구간에서 선형 모델을 유의하게 이겼고,
> 과소예측률은 절반 이하로 떨어졌다. **Transformer를 채택한다.**

### 왜 이전에는 실패했는가

여섯 번의 단일 관측소 실험이 전부 baseline에 못 미쳤던 이유는 두 가지였다.

**① 표본 부족** — 급상승 학습 표본 1,150개 vs 파라미터 15,757개.
전국 데이터로 17,303개가 되자 같은 구조가 이기기 시작했다.

**② 비교 조건 불일치** — baseline(0.373m)은 *미호강교 한 곳에서 상류 관측소 2곳
정보를 쓰며 같은 하천의 미래*를 맞히는 문제였고, Transformer는 *처음 보는 하천을
상류 없이* 맞히고 있었다. 같은 자로 재지 않은 채 "미달"로 판정할 뻔했다.

### 학습 중 발견한 함정 두 가지

**정규화가 손실 가중을 무력화했다.**
수위를 경보수위로 나누자 Y값이 1/8로 작아졌는데(0.3m → 0.037), 가중식이
`w = 1 + 8·|true|` 인 비례식이라 가중이 3.4배에서 1.3배로 떨어졌다.
급상승 표본을 15배 늘려놓고 정작 그 표본에 가중이 걸리지 않아 loss가 3 epoch 만에 멈췄다.
→ **임계 기반 가중으로 교체** (경보수위 3% 이상 15배, 10% 이상 40배).
   수정 직후 loss가 4.5배로 뛰며 학습이 살아났다.

**모델 크기의 정답이 데이터에 따라 뒤집혔다.**
```
표본  1,150 vs 파라미터 15,757  →  과적합. 모델 축소가 정답
표본 17,303 vs 파라미터 15,757  →  용량 부족. 모델 확대가 정답
```
같은 하이퍼파라미터가 데이터가 바뀌자 정반대 방향으로 틀렸다.

### 한계 (과대 해석 금지)

- test 급상승 표본 **1,613건**. 적지는 않으나 관측소 7곳에서 나온 값이다
- **전체 RMSE는 선형회귀가 3배 우수**(0.0124 vs 0.0380). 평상시 정확도를 희생한 결과이며,
  이는 의도한 교환이지만 "모든 면에서 우수"가 아니다
- 상류 관측소 정보가 입력에 없다. 오송에는 상류 2곳이 있으므로 **실제 적용 시 더 나을 수 있다**
- val 최고(0.0742)보다 test(0.0567)가 좋게 나왔다. test 관측소가 상대적으로 쉬웠을 가능성

## 9.5 GBDT 추가 · 앙상블 · 목적함수 전환 (2026-08-18)

### 9.5.1 트리 모델을 다시 꺼낸 이유

앞서 LightGBM을 폐기한 것은 *침수흔적도로 침수 여부를 학습*하려던 때였고,
독립 강우사건이 3개뿐이라 성능 측정 자체가 불가능했기 때문이다.
**수위 예측은 조건이 전혀 다르다** — 표본 66만, 급상승 1.7만이고,
시계열을 lag·누적·변화율로 펴면 전형적인 **테이블 문제**가 된다.

결과적으로 GBDT는 **학습 2초**에 균형 잡힌 성능을 냈다(Transformer는 19분).

### 9.5.2 세 모델의 성격이 갈린다

```
TEST (처음 보는 관측소 7곳 · 급상승 1,613건 · 판정문턱 = 경보수위의 70%)

모델              전체RMSE  급상승RMSE  과소예측   재현율  정밀도    F1
Persistence        0.0156    0.0947   100.0%   82.4%   82.4%  0.824
선형회귀            0.0123    0.0688    91.8%   84.6%   90.3%  0.874
GBDT              0.0138    0.0616    82.1%   84.1%   86.4%  0.852
Transformer       0.0380    0.0567    44.9%   83.2%   83.7%  0.835
```

- **선형회귀** — 경보 정밀도 90.3%. 헛경보가 가장 적다
- **GBDT** — 어느 지표에서도 꼴찌가 아니다. 게다가 설명 가능
- **Transformer** — 급상승 RMSE·과소예측률에서 유일하게 압도적(44.9%)

### 9.5.3 목적함수가 모델 선택을 뒤집는다

앙상블 가중치를 **무엇으로 최적화하느냐**에 따라 조합이 정반대가 됐다.

```
[RMSE 기준]  선형 0.00 · GBDT 0.23 · Transformer 0.77
[F2  기준]  선형 0.45 · GBDT 0.55 · Transformer 0.00
```

최종 경보 판정 성능:

```
모델                  문턱   재현율   정밀도  놓침  헛경보    F2
선형회귀              0.70   84.6%   90.3%   56     33   0.857
GBDT                 0.70   84.1%   86.4%   58     48   0.845
Transformer          0.70   83.2%   83.7%   61     59   0.833
앙상블(F2 기준)        0.65   95.1%   71.6%   18    137   0.892
```

> **놓치는 위험이 56건 → 18건으로 68% 감소했다.**
> 헛경보는 33→137건으로 늘었지만, 재난에서 미탐의 비용은 오경보와 비교할 수 없다.
> F2(재현율 2배 가중)가 이 비대칭을 반영한다.

### 9.5.4 개선 크기 비교 — 어디에 노력을 쓸 것인가

| 시도 | 효과 |
|---|---|
| GBDT 하이퍼파라미터 튜닝 (18조합) | val 0.0845~0.0868, **차이 3% — 사실상 없음** |
| 앙상블 (RMSE 기준) | 0.0567 → 0.0537, **5% 개선** |
| **목적함수 전환 (RMSE → F2)** | **놓침 68% 감소** |

**하이퍼파라미터를 만지는 것보다 평가 기준을 목적에 맞추는 것이 압도적으로 효과적이었다.**

### 9.5.5 경보 문턱을 낮춘 이유 (데이터가 강제한 결정)

처음에는 '경보수위(정규화 1.0) 초과'를 판정 기준으로 삼았으나 F2가 전부 0으로 나왔다.

```
경보 100% 초과 표본:  train 182건(0.027%) · val 0건 · test 34건
```

**val 관측소 7곳은 22년 홍수기 동안 한 번도 경보수위를 넘지 않았다**(최고 91%).
양성 표본이 없으니 최적화도 평가도 불가능하다.

→ 판정 기준을 **주의 단계(경보수위의 70%)** 로 조정하자 val 150건 / test 364건이 확보됐다.
실제 하천 경보가 관심·주의·경계·심각 **단계별로 운영되는 이유**를 데이터로 확인한 셈이다.

### 9.5.6 GBDT 피처 중요도 — 설명 가능성

```
rain_c3    (3시간 누적강수)  36.3%  ██████████████████
ch_d1      (1시간 변화)      17.3%  ████████
d1h        (1시간 수위변화)    9.1%  ████
rain_now   (현재 강수)        9.1%  ████
wl_vs_mean (평균 대비 수위)    4.3%  ██
```

**강수 관련 피처가 45% 이상.** 물리적으로 타당하고, *"모델이 무엇을 보고 판단하는가"* 를
그림 한 장으로 제시할 수 있다. Transformer의 attention보다 훨씬 설명하기 쉽다.

### 9.5.7 최종 채택

```
경보 판정 : 앙상블(선형 0.45 + GBDT 0.55), 문턱 0.65  → 재현율 95.1%
수위 예측 : 앙상블(GBDT 0.23 + Transformer 0.77)      → 급상승 RMSE 0.0537
설명 자료 : GBDT 피처 중요도
```

두 목적이 다른 조합을 요구하므로 **용도별로 다른 앙상블을 쓴다.**

## 9.6 재수집 후 재학습 (2026-08-20)

### 데이터가 2배로 — 그리고 정제기의 결함이 드러났다

```
수집   59개소 111만건 → 242만건 (HRFCO 빈 응답 재시도 강화)
```

전국으로 확장하자 v1 정제 규칙의 **두 결함**이 보였다.

| 결함 | 내용 |
|---|---|
| ① 강수 대조 지점 고정 | `load_rain()`이 청주(131) 고정. 관측소는 ASOS 25지점에 흩어져 있다 |
| ② 변화율 임계가 미호천 전용 | 2.0m/h는 한 하천에서 뽑은 값. 정상 변동폭(p99.9)이 하천마다 0.27~0.89m/h |

그 결과 v1이 flag한 342건 중 **315건이 진짜 홍수**였다.

```
영월대교 2006-07-16  11.09m   ← 경보수위 8.5m 초과. 2006 중부호우
승촌보  2023-06-28   9.12m   → 24시간에 걸쳐 완만히 감쇠 = 유출곡선
```

**급상승 표본은 우리가 가장 아쉬워하는 자원인데, 그걸 지우고 있었다.**

### v2 판정 — 되돌아오는 방식으로 가른다

```
임계 = max(2.0, 4 x 그 관측소의 p99.9)      ← 낮추지 않는다. 급한 하천만 올린다
급등 → 72시간 내 급락 → **급락 후 수위가 급등 전 부근으로 복귀**하면 오류
직전 24h 강수 30mm 이상이면 판정 보류 (그 관측소의 ASOS 기준)
```

센서 오류는 튀었다가 정확히 원래 값으로 떨어지고, 홍수는 유출곡선을 그리며 서서히 빠진다.
→ **27건 · 1개소**만 남았고, 전부 명백한 오류였다(밀양 삼상교 1.49→9.99→1.44m, 9.99는 센서 상한).

→ `scripts/clean_waterlevel2.py`

### 학습 표본

```
              이전                        이번
train   666,057 / 급상승 17,303   →  1,722,366 / 급상승 33,515  (39개소)
val      88,606 / 급상승  6,370   →    286,540 / 급상승 10,659  ( 8개소)
test     86,335 / 급상승  1,613   →    346,583 / 급상승  6,900  ( 8개소)
```

> 관측소가 47→55개로 늘어 **분할 자체가 바뀌었다.** 예전 수치와 직접 비교할 수 없어
> 새 test에서 baseline을 다시 쟀다.

### 결과 (새 test · 처음 보는 관측소 8곳)

```
모델                    전체 RMSE   급상승 RMSE   과소예측률
① Persistence            0.0171      0.1027      100.0%
② 선형회귀(Ridge)         0.0134      0.0773       93.7%
③ Transformer            0.0296      0.0626       63.1%
                                     ↑ ②대비 -19.0%   ↑ -30.6%p
```

### Transformer 경로의 기여

DLinear 단독 모델을 같은 데이터·분할·손실·시드·lr 후보(1e-4, 3e-4, 1e-3, 3e-3, 15에폭)로 따로 학습해 비교했다.
lr은 val 급상승 RMSE로 골랐고(1e-3, 6에폭), test는 1회만 평가했다.
결합 모델은 lr 탐색이 중간에 멈춰 3e-4(1에폭)로 정해졌다(아래 "학습을 중간에 멈춘 경위"). 두 모델의 lr 탐색 범위는 같지 않다.

```
TEST = 처음 보는 관측소 8곳 · 급상승 6,900건

모델                     전체 RMSE   급상승 RMSE   과소예측률   val 급상승
Ridge                     0.0134      0.0773       93.7%        -
DLinear 단독               0.0367      0.0648       60.8%      0.0740
DLinear + Transformer     0.0296      0.0626       63.1%      0.0697
```

- Ridge 대비 급상승 RMSE 개선 19% 중 16%p는 DLinear 단독으로 나온다. 급상승 가중 손실로 학습한 DLinear가 개선의 대부분이다.
- Transformer 결합은 급상승 RMSE를 3.4%(val 5.8%), 전체 RMSE를 19% 더 줄인다. 과소예측률은 줄이지 못했다.
- 결합 모델의 게이트 α는 −0.0024로 작지만, α·B는 출력 변동의 17.5%를 차지한다. 같은 결합 모델에서 경로 B를 끄면
  급상승 RMSE 0.0636, 과소예측률 67.2%다.
- DLinear 학습 중 val 급상승 RMSE가 에폭마다 0.074~0.092로 흔들렸고 시드 1개로 측정했다.
  Transformer 결합의 3~6% 차이는 여러 시드로 반복해야 확정할 수 있다.
- 최종 입력에는 상류 관측소 수위가 없다(관측소 자체 수위·강수 9채널). 변수 간 attention을 쓰는 경로 B의
  설계 의도(§3.2)는 이 조건에서 충분히 검증되지 않았다.

→ `python scripts/train_multi.py --epochs 15 --no-transformer`

### 급상승 구간 정의

다중 관측소 실험(§9.4 이후)은 "3시간 변화량 ≥ 0.03 × 경보수위"를 급상승으로 본다(관측소별 약 0.21~0.36m).
단일 관측소 실험(§9.1)은 0.3m 고정이었다. 두 구간의 수치는 직접 비교하지 않는다.

### 학습을 중간에 멈춘 경위

lr 3종 × 15에폭을 계획했으나 시간이 부족해 중단했다. 그 과정에서 두 가지를 배웠다.

**① 에폭을 돌려도 급상승은 나아지지 않는다**

```
lr=3e-4  ep 1   val_all 0.0351   val_rise 0.0697  (최고)
         ep 6   val_all 0.0257   val_rise 0.0754
         ep 15  val_all 0.0246   val_rise 0.0732
```

전체 RMSE는 계속 좋아지는데 급상승은 나빠진다. 표본의 98%인 평수위로 모델이 끌려간다.
**최고 성능이 1에폭에 나온다**는 것은 급상승 가중 손실이 아직 충분하지 않다는 뜻이다.

**② 체크포인트는 lr마다 저장해야 한다**

`train_multi.py`가 모든 lr을 끝낸 뒤에만 저장하는 구조라, 중단 시 전부 날아갔다.
시드가 고정(42)이고 스케줄러는 에폭 종료 후 작동하므로 1에폭만 재현해 복구했다
(val_rise 0.0697로 로그와 정확히 일치). → lr별 저장을 추가했다.

## 9.7 오송 참사 당일 재현

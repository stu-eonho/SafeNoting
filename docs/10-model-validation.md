# 10. 모델 타당성 검증 — 실제 데이터로 성능을 측정한 기록

> 작성 2026-08-15 · "우리 데이터로 이 모델이 성능을 낼 수 있는가"를 **추정이 아니라 실측**으로 확인한 문서.
> 결론부터: **LightGBM 학습은 데이터상 불가능**하고, **물리 모델은 적용 범위 안에서 유효**하다.

---

## 1. 학습 데이터 실사 — LightGBM이 불가능한 이유

### 1.1 표본 수가 5,218건이 아니다

충북 침수흔적 **5,218건**을 확보했고, 처음에는 이걸 ML 학습 데이터로 계획했다.
그런데 **발생 연도로 묶어보니 실체가 달랐다.**

| 사건 | 폴리곤 수 | 비중 |
|---|---:|---:|
| **2017-07-16 중부호우** | 3,344 | 64.1% |
| 2020-08 집중호우 | 811 | 15.5% |
| 2006 집중호우 | 628 | 12.0% |
| 2020 집중호우(별도 표기) | 99 | 1.9% |
| 2018 호우 | 54 | 1.0% |
| 나머지 8개 연도 | 282 | 5.4% |

> **레코드는 5,218건이지만, 독립 강우사건은 6개다. 실질적으로는 3개(2017·2020·2006)다.**

오송이 속한 **흥덕구는 더 심하다**: 802건 중 **747건(93%)이 2017년 단일 사건**.

### 1.2 이것이 왜 치명적인가

ML로 "강수량 → 침수 위험"을 학습시키려면, 강수 조건이 **다양해야** 한다.
그런데 우리 데이터는:

```
2017년 폴리곤 3,344건  →  강수 피처값은 전부 동일 (같은 날 같은 비)
2020년 폴리곤   811건  →  전부 동일
2006년 폴리곤   628건  →  전부 동일
```

- **독립 표본 3개로 학습하는 것과 같다.** 3,344건은 한 사건의 공간적 세분화일 뿐이다.
- 무작위 train/test 분할을 하면 **같은 사건의 인접 폴리곤이 양쪽에 섞여** 데이터 누수가 발생한다.
  → 검증 점수는 높게 나오지만 **전부 거짓**이다.
- 올바르게 **사건 단위로 분할**하면 → 학습 2건 / 검증 1건. 모델이라 부를 수 없다.

### 1.3 여기에 음성 라벨도 없다 (PU 문제)

침수흔적도는 **침수된 곳만** 기록한다. 기록 없는 곳은 "안전"이 아니라 **"조사 안 됨"**이다.
이걸 0으로 학습하면 → *조사되지 않은 지역을 안전하다고 예측하는 모델*.
**재난 시스템에서 가장 위험한 형태의 오류.**

### 판정: **LightGBM 침수예측 모델은 폐기한다.**

성능이 안 나오는 게 아니라, **성능을 측정하는 것 자체가 불가능**하다.
무작위 분할로 높은 점수를 만들 수는 있지만, 그것은 데이터 누수의 결과다.

## 2. 대신 물리 모델을 실측 검증했다

### 2.1 검증 설계

침수흔적도를 **학습 라벨이 아니라 정답지(ground truth)** 로 쓰면, 학습 없이도 정량 평가가 가능하다.

```
판정식:   지반고(DEM) < 수면 해발고도   →  "침수" 예측
수면 해발 = 영점표고 19.643 m + 관측수위

검증 대상: 2017-07-16 중부호우
관측수위 : 미호천교(3011665) 최고 9.28 m (7/16 14시)  ← HRFCO 실측 조회
수면 해발: 19.643 + 9.28 = 28.92 m
정답지   : 궁평2지하차도 5km 이내 2017년 침수흔적 442건
지반고   : SRTM 30m DEM (442건 전부 조회 성공)
```

> 이 검증은 일회성 분석으로 수행했다. 조회한 지반고를 저장하지 않아 저장소의 스크립트로는 재현되지 않는다.
> 침수흔적 442건과 지하차도 거리는 수집 원자료(저장소 미포함)에 있다.

> 양성 샘플만 존재하므로 측정 가능한 지표는 **재현율(Recall)** 뿐이다.
> 정밀도는 음성 라벨이 없어 측정 불가 — 이 한계를 숨기지 않는다.

### 2.2 결과 — 전체 재현율 37.1% (164/442)

숫자만 보면 실패다. **그런데 쪼개보면 이야기가 완전히 달라진다.**

### 2.3 거리별 재현율

| 궁평2지하차도로부터 거리 | 건수 | 재현율 | 지반고 중앙값 |
|---|---:|---:|---:|
| **0 ~ 0.5 km** | 15 | **93.3%** | 27 m |
| **0.5 ~ 1 km** | 20 | **80.0%** | 28 m |
| 1 ~ 2 km | 50 | 50.0% | 28 m |
| 2 ~ 3 km | 71 | 33.8% | 29 m |
| 3 ~ 5 km | 286 | 29.7% | 30 m |

> **물리 모델은 지하차도 반경 1km 이내에서 80~93% 재현율을 낸다. 멀어지면 무력해진다.**

이건 실패가 아니라 **적용 범위(domain of validity)가 측정된 것**이다.

거리는 수위 관측소가 아니라 **궁평2지하차도로부터** 잰 값이다. 관측소(미호천교)는 지하차도에서
약 478m 떨어져 있어 0.5km 구간의 흔적들은 관측소와도 가깝지만, 이 표는 "관측소에서 멀어질수록"이
아니라 "분석 지점에서 멀어질수록"의 재현율이다. 관측소 기준 거리로 다시 묶으면 구간별 건수가
2/32/66/83/248로 달라지며, 그 기준의 재현율은 지반고를 다시 조회해야 계산할 수 있다.

### 2.4 왜 멀어지면 안 맞는가 — 원인별 분해

| 침수 원인 | 건수 | 재현율 |
|---|---:|---:|
| 내수침수 (배수 불량) | 405 | 40.2% |
| 하천범람 | 37 | 2.7% |

오송 인근 침수흔적의 **92%가 "집중호우로 내부침수"**, 즉 **하천범람이 아니라 배수 불량**이다.
물리 모델은 하천 수위만 본다. **내수침수는 원리적으로 설명할 수 없다.** 당연한 결과다.

### 2.5 발견한 방법론적 오류 — 하천 수면은 수평이 아니다

"하천범람" 37건의 재현율이 **2.7%로 오히려 더 낮은 것**은 직관에 반한다. 원인을 추적한 결과:

> **우리는 관측소 한 지점의 수면 해발(28.92m)을 반경 5km 전체에 동일하게 적용했다.**
> 그런데 하천 수면은 **상류로 갈수록 높다.** 수평이 아니다.
> 상류 3km 지점의 실제 수면은 28.92m보다 수 m 높으므로, 우리 모델은 그곳을 과소평가한다.

이건 모델의 한계가 아니라 **구현 오류**이며, **수정 가능**하다 → §4.3.

### 2.6 놓친 278건은 아깝게 놓쳤다

지반고가 수면보다 높아 놓친 278건의 **초과분 중앙값은 +1.1 m**.
SRTM 30m DEM의 수직 오차(±수 m)와 같은 크기다.

> **즉 상당수는 모델이 틀린 게 아니라 DEM 해상도 때문에 놓친 것이다.**
> **5m DEM으로 교체하면 재현율이 유의하게 오른다** — 5m DEM을 받아야 할 정량적 근거.

(극단값인 지반고 76m·70m 지점은 명백한 산간 내수침수로, DEM 문제가 아니라 범위 밖이다.)

## 3. 결정

| 모듈 | 결정 | 근거 |
|---|---|---|
| 침수 판정 | 물리 계산 (하천 수면고 vs 지반고) | 지하차도 반경 1km 이내 재현율 80~93% (§2.3) |
| 침수흔적도 기반 침수 예측 ML | 폐기 | 독립 강우사건 3개, 음성 라벨 없음 (§1) |

## 4. 데이터 전처리 설계

### 4.1 좌표계 통일 — 모든 것을 EPSG:4326으로

| 소스 | 원본 | 변환 |
|---|---|---|
| 침수흔적도 GEOM | EPSG:3857 | `m3857_to_wgs()` (구현·검증 완료) |
| HRFCO 관측소 | DMS 문자열 `127-21-02` | `dms()` (구현·검증 완료) |
| 대피소/카카오 | EPSG:4326 | 그대로 |
| 국토지리원 DEM | EPSG:5186 예상 | `pyproj` (파일 수령 후) |
| 기상청 격자 | LCC nx/ny | `latlon_to_grid()` (검증 완료) |

### 4.2 침수흔적 폴리곤 전처리

**중심점만 쓰면 안 된다.** 중앙 면적이 8,832m²(한 변 ≈94m)라 중심점 하나로는 대표성이 없다.

```
1) GEOM 파싱 → EPSG:4326 링
2) 30m 격자로 래스터화 (중심점 대신 폴리곤 전체를 셀로 전개)
3) 셀 속성: 침수심(FLDN_DOWA), 등급(FLDN_GRD), 원인(FLDN_CS_DTL_NM), 사건ID
4) 원인 분류: 하천범람 / 내수침수 / 기타  ← §2.4에서 성능이 갈리므로 반드시 분리
5) 중복 셀은 최대 침수심으로 병합
```

**point-in-polygon으로 "이 건물이 침수 구역인가"를 판정하지 말 것.**
폴리곤이 작아 대부분 빗나간다(이전에 385개 대피소 전부 0건 매칭). **버퍼 거리 + 고도**로 판정한다.

### 4.3 하천 수면고 보간 — §2.5 오류 수정

관측소 한 점의 수면을 전역에 쓰지 않는다.

```
1) 미호천 중심선을 OSM(waterway=river)에서 추출
2) 중심선을 따라 하도거리(chainage) 계산
3) 관측소 수면 해발을 기준점으로, 하천경사(약 0.3~1‰)를 적용해 상·하류 보간
   수면(s) = 28.92 + 경사 × (관측소로부터 상류거리)
4) 각 지점의 "가장 가까운 하천 지점"의 수면고와 비교
```

→ §2.4의 하천범람 재현율 2.7% 문제를 직접 겨냥한 수정.

### 4.4 DEM 전처리

```
1) SRTM 30m → 즉시 사용 (현재)   /  국토지리원 5m → 수령 시 교체
2) 대상 범위로 클립: 36.58~36.68 / 127.28~127.40
3) EPSG:4326 재투영
4) 파생: 경사(slope), 저지대 지수(주변 대비 상대고도)
5) 좌표→고도 조회는 최근접이 아니라 이중선형 보간
```

### 4.5 도로망 전처리

```
1) osmnx: graph_from_bbox(network_type='drive' + 'walk' 각각)
2) 지하차도 태깅: tunnel=yes 또는 layer<0  → 침수경보 시 cost=∞  (검증 완료)
3) 각 엣지에 부여
   - 중점 지반고 (DEM)
   - 최근접 하천거리
   - 최근접 침수흔적 거리 + 그 지점 침수심
4) 대피소 385곳 → 최근접 도로노드 스냅
```

### 4.6 피해야 할 처리

- **무작위 train/test 분할** — 반드시 사건 단위 분할. 인접 폴리곤 누수.
- **"침수흔적 없음 = 안전" 라벨링** — 미조사와 안전은 다르다.
- **재현율만 보고 "정확도"라 부르기** — 음성 라벨이 없어 정밀도는 측정 불가. 표기를 정확히.
- **관측소 수면고를 광역에 적용** — §2.5.
